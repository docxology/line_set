`4670c48cc490636455f2eac09ba4396baed9ffd7`, in a detached worktree with a
managed `projects/working/line_set` leaf link to an isolated committed clone.
External interpreters, environments, caches and temporary files remain on
GitVault. Process-scoped `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=core.fsmonitor`,
`GIT_CONFIG_VALUE_0=false` is used; no global or repository config is changed.

The original retry was bounded at 30 minutes and remained blocked in pipe
writes after approximately 14 minutes. It was stopped only after the clean
clone passed validation and rendered provenance. A manual `git check-ignore
-v -z --stdin` with `GIT_TRACE=1` completed immediately; native samples showed
the stalled Python and Git processes both waiting in writes. This does not
establish a universal cause. Fresh-clone checks then exposed and corrected two
setup errors: an alias outside the managed lifecycle and an engine archive
without a Git source index. No engine code or check was changed or disabled.

Inherited clipping in the order, pipeline, exemption and vocabulary figures
remains visible and belongs to the deep-review owner's figure work. Passing
render validation establishes generation and input/output binding, not
