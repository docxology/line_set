# Line Set 0.6.0

This packet defines the release scope and its verification boundary. Publication
is identified by the remote main branch and annotated `v0.6.0` tag; a prepared
package version, citation date, or successful individual gate is not that proof.

## Scope

This release coordinates refinements across the eight native instruments,
Line Set, and Witness Register. The admitted colors remain Red, Black, Golden,
White, Silver, Violet, Blue, and Green. Line Set and Witness Register remain
colorless companions; no common evaluator, ranking, or new color is introduced.

Publication authority is limited to ordinary main-branch pushes and annotated
version tags. GitHub Release objects, Zenodo publication, hook changes, and
collection-setting changes are outside this publication scope.

## Changed contracts

- Maintained prose and owned interfaces use American English. Removed spelling
  aliases are not retained as compatibility paths; historical evidence preserves
  its original identities and bytes.
- Canonical measurement comparison preserves nested scalar types. Boolean and
  integer values, or integer and floating-point values, cannot match merely
  through Python's numeric equality.
- Canonical manuscript readings require actual pinned producer snapshots.
  Readable, collision-free but unpinned sources cannot produce a canonical record.
- Explicit public reading views use outer schema `2.0-public`, withholding
  selected source revisions and module paths only after full underlying pinned
  admission. The full `2.0` canonical format is unchanged. Public comparison
  cannot establish continuity of a withheld private revision.
- Figure registry 2.0 uses canonical `alt_text` for the external renderer.
  Authored descriptions remain distinct from captions. Native declaration,
  reading, evaluation, and transport schema identities are independent of this
  figure-metadata cutover.
- Compiled volumes keep the merged bibliography in the final References
  section. Empty source reference pages, including citeproc placeholders,
  are structural stubs; source reference prose and examples remain intact.
- Blue publication diagrams use the cover's opaque house-paper canvas, retaining
  label contrast in dark readers without overriding the reader's color scheme.
- Red manifest schema `1.2` separates publication-content custody from engine
  attestations. Native comparison/binding evidence remains authenticated; final
  native strict approval and complete current engine provenance must coexist
  without recursively hashing each other's catalogs.
- The shared renderer honors registered native test markers and explicit marker
  expressions, and resolves split-page destinations using actual browser anchor
  semantics. Its correction is a source-only SDK change, not an SDK version bump.
- The current manuscript lives in `docs/manuscript/`; the former root manuscript
  is retained verbatim under `evidence/manuscript-20260729/`. Existing records and
  historical native cohorts are not rewritten to appear current.

The [refinement note](../refinement-20261106.md) records family boundaries,
interface changes, historical custody, and the unadmitted Amber/Copper hypotheses.

## Publication acceptance

Release approval requires freshly generated and verified native artifacts,
actual final producer captures, the current synthetic
transport cohort with disclosure review, both Line Set dependency lanes, and
standalone and complete-volume publication checks. Stage03, native gates,
Stage04, and current rendered provenance must each pass; a successful downstream
gate does not override an earlier render failure. Actual section-page navigation
and the existing rendered-placeholder predicate are separate acceptance checks.
A complete volume preserves its raw authored assembly and separately records
any genuine native-resolved manuscript projection. It does not hand-substitute
native variables or claim that a hydrated derivative is unchanged authored prose.
Only then may the approved main pushes and annotated tags proceed.
